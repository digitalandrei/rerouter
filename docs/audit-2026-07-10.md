# Rerouter Full Re-Audit (2026-07-10)

**Date:** 2026-07-10
**Starting revision:** `f99708b` on `main`
**Scope:** doctrine, repository instructions, documentation, Rust controller,
React frontend, migrations, deployment assets, configuration, and CI
**Disposition:** findings were remediated in the working tree during the audit

## Executive verdict

The re-audit found several material gaps. The most immediate deployment defect
was an Nginx trust-order error: restoring the visitor address before a
server-level Cloudflare `allow` check caused legitimate proxied requests to be
evaluated as non-Cloudflare clients and denied. In the controller, the largest
safety gaps involved durable pre-action intent, fail-closed database behavior,
action concurrency, preview-to-execution binding, flow-trigger identity, alert
loss, and authentication races.

Those findings are fixed in this working tree. The shipped posture remains
observe-only, automatic actions remain independently disabled, and every
execution path now passes through the same serialized, inventory-bounded,
audited guard and executor. No known finding defeats that default posture.

This is not a claim of zero residual risk. In particular, UDP flow exporters
are not cryptographically authenticated, device verification still depends on
command-specific text matching, SNMP v2c and legacy IOS SSH weaken the device
management transport, and browser-level end-to-end coverage does not yet exist.
These are documented under [Residual risks](#residual-risks).

## Method

The audit traced each documented safety claim to its implementation and then
followed each mutation and automatic-action path through authorization,
validation, database ownership, concurrency, actuation, verification,
finalization, alerting, and recovery. It also checked:

- schema history and fresh-database migration behavior;
- NetFlow v9 and sFlow v5 parsing, exporter identity, aggregation bounds, and
  rule-trigger propagation;
- SNMP discovery, freshness, counter completeness, and reachability handling;
- session, password, TOTP, recovery-code, role, and last-superadmin behavior;
- frontend/API contract alignment and stale-state presentation;
- Nginx request phases, Cloudflare origin ACL generation, systemd hardening,
  environment/config examples, and CI gates;
- links and factual consistency across doctrine, runbooks, skills, agents, and
  project-level instructions.

Historical migrations were not rewritten. Historical audit documents remain
as point-in-time records and are superseded operationally by this report.

## Remediated findings

### 1. Origin access control and deployment

**Finding:** `real_ip_header` replaced `$remote_addr` before Nginx evaluated the
server-level Cloudflare `allow` list. A valid request arriving from a Cloudflare
proxy was therefore denied using the restored visitor address.

**Resolution:** the origin ACL now evaluates the actual TCP peer. Only after
that ACL succeeds is `CF-Connecting-IP` forwarded to the loopback API. A new
atomic updater installs sanity-checked Cloudflare IPv4/IPv6 ranges, an exact-host
guard blocks other Cloudflare zones, and the systemd unit gained additional
device, hostname, and `/proc` isolation.

### 2. Durable action intent and exact correlation

**Finding:** some failure windows existed between deciding to act, persisting
intent, issuing SSH, and linking locks/alerts to the resulting reroute.

**Resolution:** required audit and started-alert rows are persisted before SSH;
actions carry exact correlation identifiers; reservations and advisory locks use
the same database connection; uncertain finalization is conservative; and all
background tasks are supervised. Any ambiguous SSH apply failure now becomes
uncertain and locks the device, even if a later text check sees the intended
configuration.

### 3. Fail-closed safety gates

**Finding:** selected database read failures could inherit permissive defaults,
and cooldown enforcement depended too heavily on current state.

**Resolution:** an unreadable operating mode resolves to observe, an unreadable
maintenance setting resolves to locked, and other unreadable enablement gates
resolve to disabled. Cooldowns also consult execution history, while rollback
bypasses throttles only where corrective action requires it and still obeys
mode, locks, reachability, and serialization.

### 4. Preview and rollback integrity

**Finding:** previewed plans were not universally bound to the later mutation,
and rollback eligibility/concurrency needed stronger ownership.

**Resolution:** manual actions, rule applies, and rollbacks require a five-minute,
single-use, hashed token bound to the user, action, target, exact rendered plan,
and audit reason. Flow targets are resolved once. Rollback requires a prior
execution that reached the device and rejects conflicting active or successful
sibling rollbacks.

### 5. Inventory, SSH identity, and template policy

**Finding:** stale or partial inventory and ambiguous template verification
could allow an action to outgrow its known target or appear verified vacuously.

**Resolution:** routing inventory is reconciled transactionally and expires;
prefix actions must remain inside fresh announced inventory; unknown interfaces
block disruptive actions; TOFU host-key persistence is mandatory and detects
concurrent mismatch; the SSH command set fails closed; templates reject empty
apply plans and require meaningful read-only verification. Destructive template
classes are explicitly manual-only. Device enrollment no longer suggests the
conventional public SNMP community and rejects empty communities, zero ports,
and out-of-range polling intervals. Persisted MSS verification output is filtered
to the relevant line rather than retaining an entire interface configuration.

### 6. Flow and SNMP telemetry

**Finding:** exporter identity did not include protocol/domain identity, parser
and aggregation state needed stronger bounds, ambiguous flow-only rules could
act on weak targets, and partial SNMP polls could appear healthy. Flow rule
evaluation also selected the latest bucket that matched a port rather than the
latest interface bucket and lacked indexes for its selector, which could retain
a stale non-zero value while scanning millions of historical rows.

**Resolution:** exporter identity now includes source plus protocol observation
domain; template and aggregation state are bounded and saturating; failed
buckets are retained for retry; interface lookups and bucket writes are
transactional. Flow-driven automatic execution has a separate global switch,
per-device enrollment, confidence requirement, fresh same-interface SNMP ratio,
and persisted alert/event before SSH. Protocol-only selectors are rejected and
legacy ambiguous rules are disabled. SNMP now requires complete packet and
octet counter sets and performs resilient `ifName`/`ifDescr` discovery. Flow
rules now anchor every selector to the latest closed interface bucket, treat a
missing current selector as a low-confidence zero, and use composite indexes for
bounded latest-bucket evaluation and exporter cleanup.

### 7. Authentication and authorization

**Finding:** initial TOTP enrollment was insufficiently separated from login,
accepted TOTP steps could be replayed, and some session/lockout/recovery paths
needed transaction ownership or stricter failure behavior.

**Resolution:** first enrollment uses an independent high-entropy credential;
accepted TOTP time steps are consumed under row lock and cannot be reused;
login has IP throttling and transactional lockout; pre-2FA and idle sessions
expire; recovery codes are generated all-or-nothing and consumed race-safely;
malformed recovery state fails loudly; logout revocation failure is surfaced.
Email identity is normalized. The API and UI expose all five seeded roles, and
four inert permissions were removed, leaving the ten enforced permissions.
Unsafe browser mutations now require exact same-origin Fetch Metadata/Origin
signals, covering hostile sibling sites beyond the cookie's SameSite policy.

### 8. Alerts, mutations, and audit provenance

**Finding:** delivery failures could age out or be swallowed, and several CRUD
paths did not guarantee that their audit event committed with the mutation.

**Resolution:** queued alerts retry under rate limits, five failed attempts
produce a permanent-failure meta alert, decrypt and audience lookup failures do
not masquerade as success, and the dispatcher is supervised. Mutations and
their audit rows now share transactions; generic and user-management events
record request IP and user agent; last-superadmin changes are serialized; and
manual clear rolls back before closing state.

### 9. Configuration, documentation, and CI

> removed by owner decision (commit `1272ee2`). All quality gates are now
> local-only — see "Release gate (local)" in [deployment.md](deployment.md).
> The rest of this section remains accurate as a point-in-time record.

**Finding:** configuration accepted unknown keys, several defaults and docs had
drifted, and CI did not enforce all local quality gates.

**Resolution:** configuration structs reject unknown fields and validate ports,
loopback binding, intervals, auth TTL ordering, flow conflicts, and automatic
allowlists. Enabled flow collection also refuses wildcard binds. The shipped
example parses in a test. Doctrine, instructions,
runbooks, skills, agent notes, API descriptions, and frontend docs now match the
implemented system. CI uses least privilege and concurrency cancellation and
runs formatting, Clippy with denied warnings, all-target database-backed tests,
frontend typechecking, a high-severity dependency audit, and a production build.
Active telemetry/protection history now defaults to a 48-hour window, cleanup
selects the oldest 1,000 rows through dedicated timestamp indexes before
deleting by primary key, and the flow detector's latest-bucket lookups are
composite-indexed. Expired sessions, preview tokens, and cooldowns now have
indexed daily cleanup, IP throttling has a composite lookup index, and CI
compiles the optional embedded UI after producing `frontend/dist`.

## Residual risks

These items are not blockers for the shipped observe-only posture, but they are
the next worthwhile improvements, in priority order.

1. **UDP exporter identity is network-authenticated only.** NetFlow and sFlow
   source addresses are not cryptographic identities. Keep flow automatic
   actions disabled unless exporter subnets are enforced at the host/network
   edge with anti-spoofing or equivalent authenticated transport. The SNMP
   corroboration gate limits impact but does not authenticate the datagram.
2. **IOS verification is text-oriented.** Verification is constrained to
   allowlisted `show` commands with required positive/negative checks, but some
   checks remain substring based. Typed parsers per action would reduce false
   positive and firmware-format risk.
3. **Legacy device management weakens transport security.** SNMP v2c exposes its
   community and telemetry without wire encryption, while IOS compatibility
   includes SHA-1 SSH KEX/MAC and `ssh-rsa`, with CBC ciphers as a last fallback.
   The current client also prefers HMAC-SHA1 because the tested `russh` SHA-2 MAC
   path stalls against some IOS-XE versions. Keep both protocols on an isolated,
   ACL-restricted management network; prioritize SNMPv3 and a retested modern-only
   SSH profile when the client/router fleet permits.
4. **First-contact host identity is TOFU.** Pins are mandatory and every later
   mismatch fails closed, but an attacker present on the very first probe could
   become the pinned identity. Perform enrollment on a trusted management path
   and compare the displayed fingerprint out of band. A future API should accept
   a pre-provisioned expected fingerprint.
5. **Startup reconciliation is conservative, not reconstructive.** Interrupted
   actions become uncertain and lock their device; the controller does not yet
   SSH to every device at startup and reconstruct each template's exact state.
6. **Frontend failure states are uneven.** The persistent mode banner clearly
   marks controller loss, but several secondary list/detail loaders still render
   an empty collection after a read error. Add explicit per-panel retry/error
   states and a Playwright suite for login, preview, execution, roles, and stale
   telemetry workflows.
7. **Dependency and CI supply-chain checks are incomplete.** `cargo-audit` is
   not installed locally, CI has no RustSec scan, and third-party GitHub Actions
   use moving major/channel tags rather than reviewed commit SHAs. Pin both the
   scanner and action revisions.
8. **Reroute-log retention is operational.** The runbook defines retention, but
   reroute history is not automatically pruned. Add an explicit policy only
   after audit/compliance requirements are agreed.
9. **Built-in template repair is migration-oriented.** `--seed-templates`
   applies pending migrations; it does not recreate a built-in row that an
   operator deliberately deleted after its migration ran.
10. **Every environment still needs deployed-path validation.** The customer
   deployment at `emdd.vivanet.ro` passed its certificate, Nginx, systemd,
   migration, and service checks on 2026-07-10. Other environments, including
   the canonical Cloudflare-fronted vhost, still need the same checks against
   their actual certificates, includes, firewall policy, and installed binary.

## Release recommendation

Treat this working tree as a substantial safety release, not a cosmetic docs
update. Review and commit it as one coordinated controller/schema/frontend/
deployment change. The customer rollout was completed from a verified backup,
remains in observe mode, and keeps only 48 hours of active telemetry/protection
history; apply the same backup, migration, Nginx, and systemd checks to every
other environment. Do not enable flow-driven automatic actions
until the exporter network-authentication assumptions in residual item 1 are
enforced and documented for the actual deployment.
