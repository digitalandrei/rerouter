# Rerouter full-project audit — 2026-09-15

**Baseline:** `08126a182283688b91617cd0d81a0ad24ad4f233` (`main`), all 290 tracked files, plus the pre-existing uncommitted `.claude/settings.json` change.

**Disposition:** Review and remediation planning. This audit wrote the report, roadmap and plan index; it did not implement application fixes or change migrations, deployed configuration or production records. Findings and source line references below describe the reviewed baseline, not fixes delivered by this audit.

## Executive assessment

**Armed execution needs corrective work before a readiness sign-off.** The review found gaps in operator preview authorization, execution-time safety checks, verification completeness, and preservation of recovery state. It also found alert-delivery failures that affect observe-mode monitoring.

The shipped database seeds remain `observe`, with automatic actions disabled. Stable observe-mode requests return plans without applying configurations. That safeguard does not establish reliable alert delivery or safe transitions into and out of enforce mode.

All documented release checks passed with a disposable MariaDB database, including **106 Rust tests**. Additional reproductions found defects outside those tests. Current dependency scans also identify updates beyond the previously accepted RSA and derivative advisories.

**Findings:** 13 Standards findings and 33 Spec findings, mapped to 17 remediation work items. The Standards axis's highest-impact issues block keyboard workflows and error readability; the Spec axis's highest-impact issues concern authorization, verification, recovery and delivery. These are separate conclusions, not one combined quality score.

## Method, scope and evidence

- Independent Standards and Spec reviews used doctrine as the primary specification; a separate frontend review covered contracts, operator behavior and accessibility. The coordinating review covered detection, collection, data APIs, schema/retention interactions and validation, and checked accepted findings against their source.
- Scope includes repository agents, skill entrypoints/references/scripts, instructions, doctrine, historical audits, plans, all application subsystems, all 56 migrations, lockfiles and deployment assets. “Stale data” means repository content and runtime freshness/retention logic; deployed records were excluded as requested.
- Evidence is distinguished as **executed check**, **isolated reproduction**, **static trace**, or **current external advisory**. A static trace establishes a reachable code path, not a successful attack against a live deployment.
- P1 means a safety, recovery or critical operational defect to address before the affected capability is relied on; P2 is a functional, deployment or maintenance defect; P3 is lower-impact guidance/tooling debt. Confidence is stated per finding. Historical owner-approved choices are listed separately.
- Reproductions used synthetic data, local mocks and a disposable MariaDB 11.4.12 instance under `/tmp`, on loopback port 19315. No router, SMTP, Teams or production API calls were made.

## Standards

### STD-01 — Blanket destructive cleanup permission

**P2 · high confidence · configuration review.** `.claude/settings.json:5` adds `Bash(git clean *)` alongside read-only inspection permissions. There is no repository hook registration or deny rule. This can authorize removal of untracked and ignored work in a Claude session unless a stronger external policy intervenes; no deletion was observed. The bundled hook skill describes optional installation and is not an installed safeguard.

**Correction/acceptance:** Remove or narrow this allow to cleanup previews, preserving the other existing settings. Verify forced cleanup is not granted by repository permissions. [Claude permission matching](https://code.claude.com/docs/en/permissions) documents the wildcard semantics.

### STD-02 — Domain skills are undiscoverable; one has invalid YAML

**P2 · high confidence · inventory and parser checks.** `CLAUDE.md:11` promises automatic discovery, but all seven Rerouter domain skills are flat `.claude/skills/*.md` files. Project skills require `<name>/SKILL.md`. `.claude/skills/ddos-mitigation.md:3` also has an unquoted description containing `SSH: Null0`, which fails YAML parsing. Agent references can load these as documents but do not make them discoverable skills.

**Correction/acceptance:** Move all seven into named skill directories, quote the invalid description and update relative references together. Verify 27 valid, discoverable entrypoints and a working manual invocation. [Official skill locations](https://code.claude.com/docs/en/skills#choose-where-skills-load).

### STD-03 — Review workflows can inspect an empty diff

**P2 · high confidence · command comparison and static trace.** `.claude/skills/implement/SKILL.md:13` requests review before committing, while `review-since/SKILL.md:21` checks only `<base>...HEAD`. It omits staged/unstaged implementation. Conversely, `improve/references/closing-the-loop.md:30` requires the executor to commit, then line 55 checks an unqualified worktree `git diff --stat`, which excludes that commit. At this baseline the three-dot diff is empty despite the dirty settings file.

**Correction/acceptance:** Capture the starting revision and compare it with the actual result, explicitly including WIP/untracked changes where relevant. Test committed-only, staged-only, unstaged-only, untracked and mixed work; an out-of-scope committed file must be visible to review.

### STD-04 — Database compatibility instructions contradict a supported deployment

**P2 · high confidence · documentation/code comparison.** `CLAUDE.md:52` and `docs/doctrine.md:504` say MariaDB only, while `docs/database.md:14` requires compatibility with the MySQL 8.4 customer deployment. `backend-rust/tests/sql_protocol_lint.rs:1` records the resulting production transaction-protocol regression. Following the top-level instructions can recreate a customer failure while MariaDB checks pass.

**Correction/acceptance:** State MariaDB as primary with MySQL 8.4 compatibility required across doctrine, agents and SQL skills. Keep the protocol regression check and visibly distinguish MariaDB validation from actual MySQL validation.

### STD-05 — Restrictive umask makes a fresh installation inaccessible

**P2 · high confidence · actual prefixed installer reproduction.** `backend-rust/src/install.rs:82` creates directories without explicit modes; line 136 writes configuration using the process umask. Only the executable receives an explicit 0755 mode. Under umask 0077 the installer produced a root-owned 0700 application directory and 0600 config. The `rerouter` service user cannot traverse/read them. `docs/deployment.md:237` also incorrectly describes everything as service-owned.

**Correction/acceptance:** Set explicit service-readable directory/config/unit modes while retaining private secrets and preserving existing operator files. Test first install with umasks 0022 and 0077 and repeat-install content preservation. Prefer root-owned executable/config with appropriate service access.

### STD-06 — Upgrade instructions can leave the old process running

**P2 · high confidence · static operational trace.** `docs/operations-runbook.md:37` puts `--install` in a service-user toolbox even though normal installation writes root-owned locations. `backend-rust/src/install.rs:153` reloads/enables systemd and later prints `systemctl start`; neither restarts an already-running controller. An operator can replace files without running the intended new build.

**Correction/acceptance:** Separate root installation from service-user diagnostics and document an intentional restart plus executable/version and readiness verification. Validate a disposable upgrade; retain the first-install behavior that waits for operator configuration.

### STD-07 — Operational guidance retains removed gates and obsolete retention

**P3 · high confidence · source comparison.** `.claude/agents/reroute-safety-agent.md:31` requires nonexistent device `actions_enabled` and telemetry/confidence gates on every action; its checklist also forbids all rollback cooldown bypasses. These conflict with doctrine's flow-specific evidence gates and `backend-rust/src/reroute/guard.rs:183`. `.claude/agents/database-agent.md:27` prescribes 90-day rule events and 365-day alerts/reroutes, while shipped event retention is two days and reroutes are not automatically pruned.

**Correction/acceptance:** Publish precise gate applicability and current retention policy, then align agents, skills, doctrine summaries and handbook. Include the misleading `frontend/src/pages/device-detail/flows-tab.tsx:93` assertion that flows never trigger reroutes. Keep historical/de-scoped material explicitly historical; do not reintroduce removed features.

### STD-08 — Optional git hook does not enforce its advertised command coverage

**P3 · high confidence · inert-input reproduction.** `.claude/skills/git-guardrails-claude-code/scripts/block-dangerous-git.sh:3` ignores JSON/parser failures and matches literal command fragments. Equivalent Git global-option, reordered/long cleanup and option-bearing restore forms, plus malformed JSON, return success. Canonical blocked forms return exit 2. No underlying Git operation was executed.

**Correction/acceptance:** Fail closed on malformed input/missing prerequisites and use supported permission enforcement or explicit normalization of supported command forms. Test equivalent forms and safe reads. Document limits and retain optional installation; do not claim this hook is currently registered.

### STD-09 — Skill glossary gives incorrect invocation controls

**P3 · high confidence · official-document comparison.** `.claude/skills/writing-great-skills/GLOSSARY.md:17` and line 23 claim removing `description` makes a skill user-only. The main skill correctly uses `disable-model-invocation: true`; Claude can derive a missing description from body text. A workflow author could unintentionally leave model invocation enabled.

**Correction/acceptance:** Align glossary and examples with the [official invocation controls](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill). Correct stale local command references such as `/grill-me`; label external prerequisites explicitly.

### STD-10 — Customer Nginx example exceeds the documented platform baseline

**P2 · high confidence for compatibility; deployed version unverified.** `deploy/nginx/emdd.vivanet.ro.conf:27` uses `http2 on`, introduced in Nginx 1.25.1. An isolated test with Ubuntu Nginx 1.24.0 rejects it as an unknown directive; the canonical vhost already uses compatible `listen ... http2` syntax. [Nginx directive reference](https://nginx.org/en/docs/http/ngx_http_v2_module.html#http2).

**Correction/acceptance:** Use the compatible listen parameter in this example and validate both IPv4/IPv6 listeners with the intended deployment binary, keeping host/source restrictions intact. This is not a claim that the uninspected customer installation currently fails.

### FE-12 — Keyboard access is missing from operational controls

**P1 for affected keyboard-only workflows · high confidence · source/callback checks.** `frontend/src/components/searchable-select.tsx:59` provides selection only through `onMouseDown`; Enter/Space activation has no selection callback. Autocomplete suggestions, interface/flow table navigation and help triggers have related gaps (`autocomplete-input.tsx:76`, `device-detail/interfaces-tab.tsx:63`, `Flows.tsx:335`, `info-hint.tsx:17`). Several form labels are unassociated. This blocks selection and investigation without a pointer. [WCAG keyboard requirement](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html).

**Correction/acceptance:** Use native controls or a keyboard-complete combobox, explicit row links/buttons and associated labels. Exercise Arrow/Enter/Escape, Tab, blur/focus retention and screen-reader naming in a real browser. The reproduction inspected source callbacks; browser focus was not emulated.

### FE-13 — Dark error text is below minimum contrast

**P1 for error readability · high confidence · token calculation.** `frontend/src/styles/theme.css:82` and `:96` define background/card and destructive text colors with calculated contrast **1.97:1**. Small error text uses these tokens in Login, ManualReroute, Settings and Mitigations. This makes authentication/action failures difficult to read. [WCAG contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) requires 4.5:1 for these text sizes.

**Correction/acceptance:** Separate destructive fill from readable error text and verify computed foreground/background pairs reach 4.5:1 across both themes and dialog/card/input surfaces. The calculation used declared OKLCH values, not screenshots or computed browser styles.

## Spec

### SPEC-01 — Operator preview authorization is not enforced by every execution path

**P1 · high confidence · static call-chain trace.** `backend-rust/src/api/rules.rs:1005` accepts manual clear without a preview body/token, then `backend-rust/src/detection/engine.rs:1453` calls recovery rollback with `dry_run:false`. This can move traffic despite the universal operator-preview requirement in `CLAUDE.md:27`. Other endpoints only require a token when an earlier mode read says enforce (`backend-rust/src/api/reroutes.rs:208`, `:539`; `backend-rust/src/api/rules.rs:1240`), while the executor reads mode again independently. Observe→enforce between those reads permits tokenless execution. Re-rendering after token comparison can also change the authorized plan. `ActionRequest` carries no verified-preview capability.

**Correction/acceptance:** Make a consumed, actor/scoped preview capability and immutable authorized plan prerequisites for operator actuation. Add preview/confirmation to manual clear. Test every operator entrypoint, token reuse/expiry/actor mismatch, tokenless observe→enforce, changed inventory/rollback plans and partial bundles. Normal stable observe must continue rendering without actuation.

### SPEC-02 — Disarming during preflight/reservation can still execute

**P1 · high confidence · actual orchestrator with fake SSH and MariaDB barrier.** `backend-rust/src/reroute/executor.rs:200` checks mode before preflight and reservation. `backend-rust/src/reroute/guard.rs:417` rechecks maintenance/device/in-flight/uncertain state, but not operating mode or other mutable execution facts. Holding the global reservation lock, committing enforce→observe and releasing the lock produced `executed:true,state:succeeded` while the database mode was observe. No real SSH was used.

**Correction/acceptance:** Serialize final authorization/reservation against relevant safety mutations and recheck mutable mode, automatic/rule/template enablement, protection and cooldown facts at the defined actuation boundary. Document when an operation has committed to start and can no longer be recalled. Barrier tests must cover disarm/disable/protection changes before that boundary and cancellation during waits.

### SPEC-03 — Incomplete SSH output can count as successful verification

**P1 · high confidence · transport trace plus executor reproduction.** `backend-rust/src/ssh/mod.rs:1248` returns success on EOF/close without a completed prompt; `backend-rust/src/reroute/executor.rs:638` accepts an absent reject string. A blackhole withdrawal using empty fake readback reached `succeeded`. On the real transport, a verification session ending before output can produce that same empty buffer.

**Correction/acceptance:** Require completion evidence before returning a successful SSH response. Incomplete/denied/timed-out reads must leave the reroute uncertain. Preserve valid empty output from a completed filtered `show`. Test early EOF, partial output and completed-empty output separately.

### SPEC-04 — Explicit IOS rejection is persisted as an OK command

**P1 · high confidence · adapter trace and fake-SSH reproduction.** `backend-rust/src/ssh/mod.rs:1192` accumulates command responses and returns `Ok` without checking IOS errors. `backend-rust/src/reroute/executor.rs:490` records them as OK. A fake response containing `% Invalid input` plus matching readback reached `succeeded`. The real adapter has the same response contract. A denied companion command/soft clear can be hidden by an already-present route satisfying verification.

**Correction/acceptance:** Detect command-level rejection, stop subsequent configuration commands, retain partial output and propagate ambiguity to uncertain. Test rejection at each plan position and rejected soft clear even when readback matches. This is separate from replacing all accepted substring-based verification.

### SPEC-05 — Both seeded IPv4 Null-Route plans are unrenderable

**P1 · high confidence · full fresh-seed rendering reproduction.** `backend-rust/migrations/20260613001100_routing_context.sql:51` writes `{target_net}`/`{target_mask}` plans. `20260626000100_blackhole_nullroute_auto.sql:10` later changes the parameter schema to `prefix` without changing those plans or verification. Both `null_route_prefix` and `null_route_withdraw` fail with `unresolved parameter '{target_net}'`. Sixteen other seeded templates render and pass extracted production allowlist checks.

**Correction/acceptance:** Add a forward migration changing these placeholders to `prefix_net`/`prefix_mask`, plus verification `prefix_net`. Normalize legacy `{parent,target}` parameters at the rollback/legacy-action boundary without rewriting history. Test all 18 seeded plans, paired inverses, fresh install and upgrade with old action snapshots.

### SPEC-06 — IPv6 actions have no normal discovery path to eligible inventory

**P2 · high confidence · exact-parser reproduction and data-flow trace.** `backend-rust/src/ssh/mod.rs:837` accepts only IPv4 network statements, and discovery is the only writer of announced networks. The IPv6 catalog and auto-target resolver require fresh contained prefixes (`backend-rust/src/reroute/templates.rs:302`, `backend-rust/src/reroute/flow_target.rs:105`). A mixed-family BGP stanza yields only the IPv4 prefix, so normally enrolled IPv6 targets cannot pass containment.

**Correction/acceptance:** Discover supported IPv6 address-family network statements and preserve family-aware containment. Test mixed-family discovery, persistence, withdrawals and v6 preview eligibility while rejecting malformed/unsupported records.

### SPEC-07 — Historical retry rows starve new critical alerts

**P1 · high confidence · exact SQL reproduction.** `alerts/dispatcher.rs:115` selects every sufficiently old rate-limited queued row even after its target was sent or settled. The oldest-first limit is 50, and dispatch then skips completed targets. Fifty old retry→sent alerts plus a new critical uncertain alert selected only IDs 1–50; the critical alert was absent.

**Correction/acceptance:** Select unresolved per-target delivery work and exclude settled/exhausted outcomes. Ensure deferred work cannot monopolize a batch. Test more than 50 completed retry histories and prove a new critical event progresses promptly without waiting for retention.

### SPEC-08 — A crash during fanout can lose unattempted recipients/channels

**P1 · high confidence · exact SQL reproduction.** `alerts/dispatcher.rs:101` rediscovers wholly unattempted alerts or known failures/queues; `:254` sends recipients one at a time before Teams. There are no durable pending intents for every target. One successful email followed by a crash before later targets leaves zero candidate matches, even without the batch limit.

**Correction/acceptance:** Persist target fanout before delivery and track completion/retry per target. Preserve unresolved alert payload/intents beyond ordinary retention: the current blanket two-day alert deletion (`backend-rust/src/scheduler.rs:171`, `:207`) also cascades attempt history, so a long outage would otherwise defeat durable retries. Inject restart/failure after each recipient and between channels, plus SMTP absence beyond two days; all intended targets must resume and settled targets must not cause a permanent resend loop. The long-outage interaction is source-traced, not time-soak tested.

### SPEC-09 — Mandatory admin alert fanout has no recipient-user linkage

**P2 · high confidence · schema/query reproduction.** `backend-rust/src/api/notifications.rs:105` creates verified recipients without `user_id`; no normal path supplies that association. Forced critical fanout joins on it at `alerts/dispatcher.rs:460`. A same-email superadmin recipient subscribed only to rule-fired events had `user_id=NULL` and zero forced-admin matches.

**Correction/acceptance:** Persist an unambiguous user association while retaining external recipients; backfill only validated unique matches. Verify critical subscription overrides, ordinary filtering, role changes and user lifecycle behavior.

### SPEC-10 — Terminal state, audit and alerts are committed separately

**P2 · high confidence · failure-window trace.** `backend-rust/src/reroute/executor.rs:688` commits terminal state before its lock, alert and audit writes (`:742`, `:777`, `:789`). Later failures are logged without replay, while startup recovery selects in-flight states only. A crash can permanently omit terminal lifecycle records. An uncertain row still blocks new execution even if its extra lock row is absent; this finding does not claim otherwise.

**Correction/acceptance:** Commit terminal state, required correlated lock, audit and alert/outbox intent together. Fault each write and commit and restart at each boundary; preserve fail-closed state and exactly one durable lifecycle publication.

### SPEC-11 — Retention removes live recovery anchors

**P1 · high confidence · real-schema retention reproduction.** `backend-rust/src/scheduler.rs:179` prunes rule events after the default two days. `backend-rust/migrations/20260710000100_reroute_activation_links.sql:14` sets reroute links NULL on event deletion. `backend-rust/src/detection/engine.rs:1319` treats no firing event as recovery complete. Deleting an expired firing event left a succeeded automatic reroute and a firing rule, but no event/recovery link. A later clear can therefore declare recovery complete without undoing the active mitigation.

**Correction/acceptance:** Retain activation events while any associated action is active/unresolved, and derive outstanding recovery from durable action ownership rather than the latest retained event alone. Missing required ownership must produce pending/uncertain recovery. Test mitigation lifetimes beyond retention, cleared/new firing cycles and legacy NULL links.

### SPEC-12 — Device deletion destroys unresolved action history

**P1 · high confidence · real-schema deletion reproduction.** `backend-rust/src/api/devices.rs:726` deletes without an execution/history guard. `backend-rust/migrations/20260613000600_device_cli_templates.sql:18` cascades deletion to reroutes, then outputs/steps/verifications. A synthetic uncertain reroute disappeared while its old device lock remained orphaned with `reroute_id=NULL`. Re-enrolling the host gets a new ID outside that old lock and loses the original recovery parameters.

**Correction/acceptance:** Refuse hard deletion of devices with reroute history and direct operators to disable them; enforce preservation at the FK layer and serialize deletion with reservation. Test running/uncertain/succeeded/history-free cases, concurrent delete/apply and re-enrollment safety.

### SPEC-13 — First action's history blocks later actions in an ordered bundle

**P1 for multi-action mitigation reliability · high confidence · actual guard/history reproduction and call-chain trace.** `backend-rust/src/detection/engine.rs:1108` and `backend-rust/src/api/rules.rs:1340` defer explicit cooldown rows for bundles. `backend-rust/src/reroute/guard.rs:293` independently derives cooldown from every earlier `started_at`, without excluding the current bundle. The first started sibling therefore blocks subsequent same-rule actions even on another device, or same-device actions, under shipped nonzero cooldowns. A synthetic completed first sibling caused `DeviceCooldown` for the same device and `RuleCooldown` for a second device, despite `defer_cooldown:true`. Existing committed tests do not execute a complete bundle with defaults.

**Correction/acceptance:** Give a bundle a durable identity and exclude only its authorized earlier siblings from cooldown history. Preserve global per-action rate accounting and unrelated device/rule cooldowns. Test ordered same-device/cross-device bundles with default cooldowns, concurrent unrelated requests, partial failures and restart.

### SPEC-14 — Detection persistence counts evaluations and bridges stale gaps

**P1 · high confidence · actual detector/MariaDB reproduction.** `backend-rust/src/detection/engine.rs:263` increments the match count on every evaluation; `:1214` discards `sampled_at`. Aggregate evaluation runs independently of polling. Three evaluations of one unchanged metric row produced matching counts 1, 2, 3 and fired. Missing/stale observations return without resetting progress (`backend-rust/src/detection/engine.rs:243`), so a one-hour-old matching streak fired on the first fresh sample after a gap under a 60-second hold requirement.

**Correction/acceptance:** Persist consumed observation identity/time, count fresh samples once and reset unproven firing/recovery streaks across stale/invalid gaps. Define aggregate progress using fresh evidence from every member. Test repeated timestamps, unequal polling rates, controller downtime, invalid counters and recovery persistence.

### SPEC-15 — Missing telemetry fields become trusted zeroes or fabricated rates

**P1 · high confidence · source trace and public-arithmetic reproduction.** `backend-rust/src/telemetry/snmp.rs:609` tolerates missing error walks, then `:699` substitutes zero for both missing current and missing prior counters while overall sample validity depends on traffic counters. After one missing baseline, an unchanged lifetime error count of 900,000 over 30 seconds becomes 30,000 errors/s. Missing operational status is similarly treated as down by `backend-rust/src/detection/engine.rs:120`. NetFlow `v9.rs:373` also defaults absent packet/byte counters to zero without retaining presence information.

**Correction/acceptance:** Track validity and baseline timestamps per metric; unknown error/status/counter fields must not drive firing or recovery. Keep independently valid traffic measurements usable. Test omitted columns/counters, resumed unchanged baselines, status absence, bytes-only/packets-only flows and true zero measurements.

### SPEC-16 — Exporter last-packet time is refreshed without packets

**P2 · high confidence · complete receive/flush/retention trace.** `backend-rust/src/telemetry/flow/collector.rs:627` snapshots every cached exporter, including those with no closed buckets; `:824` writes `last_packet_at=UTC_TIMESTAMP()` on every flush. The actual receive timestamp `last_seen` is not persisted. A silent exporter appears recently active indefinitely, defeating the idle-exporter pruning predicate in `backend-rust/src/scheduler.rs:249`.

**Correction/acceptance:** Carry actual packet receipt time through the snapshot and update it only from received evidence; keep flush time separate if useful. Test silence across multiple flushes and beyond retention, resumed traffic and exporter eviction/recreation.

### SPEC-17 — Non-initial IPv4 fragments acquire fabricated transport ports

**P2 · high confidence · public sFlow decoder reproduction.** `backend-rust/src/telemetry/flow/sflow.rs:356` reads ports at the IPv4 header end without checking fragment offset. Fixtures with nonzero offsets 1 and 128 were decoded with destination port 53 from payload bytes. These records contaminate port-specific detection during fragmented traffic.

**Correction/acceptance:** Read transport ports only from an initial fragment with sufficient validated header bytes; retain address/volume evidence for later fragments without ports. Test initial/non-initial fragments, truncation and malformed header lengths.

### SPEC-18 — Invalid datagram framing is silently accepted

**P2 · high confidence · public decoder reproductions.** `backend-rust/src/telemetry/flow/v9.rs:221` clamps an oversized FlowSet length to remaining bytes; `sflow.rs:124` similarly clamps an opaque sample length. Both accepted fixtures with overstated lengths and returned records without reporting degradation; sFlow reported zero skipped samples. Memory bounds are protected, but malformed evidence can look fully trustworthy.

**Correction/acceptance:** Validate declared lengths/padding and report structured framing errors; never promote malformed records into automatic-action evidence. Preserve explicitly valid sibling records only with clear degradation metadata. Test short/oversized lengths, padding, truncated record counts and valid trailing padding; retain no-panic coverage.

### SPEC-19 — NetFlow templates survive exporter restart and never expire

**P2 · high confidence · public decoder reproduction.** `backend-rust/src/telemetry/flow/v9.rs:85` uses capacity-only eviction, while `:199` ignores exporter uptime/time; the collector merely stores the latest sequence. After learning a template, an uptime-reset fixture reused its ID with a reordered layout and no fresh template. The decoder returned reversed source/destination addresses and zero unknown-template errors. Old layouts can therefore misidentify traffic and automatic targets after a lost or reordered refresh. [RFC 3954 template management](https://www.rfc-editor.org/rfc/rfc3954#section-7).

**Correction/acceptance:** Expire templates and invalidate generation-specific template/sampling state on a confirmed restart. Test lost/reordered refreshes, reused IDs, normal sequence/uptime wrap, harmless reordering and lifetime expiry. Records without a current template must remain unavailable to detection.

### SPEC-20 — Explicit null cannot clear optional rule settings

**P2 · high confidence · exact request-type deserialization reproduction.** `backend-rust/src/api/rules.rs:625` uses plain `Option<Option<T>>`; without a custom decoder, explicit JSON null and an omitted field both become outer `None`. Updates at `:850` skip both. The rule editor sends null when clearing ports/protocols and recovery overrides (`frontend/src/pages/rules/rule-dialog.tsx:152`, `:175`), so the server can report success while retaining the old condition.

**Correction/acceptance:** Decode missing, explicit null and supplied value as distinct update states; validate the resulting complete rule. Test all three cases through HTTP and SQL, including clearing both protocol and port, returning recovery to defaults, and edit/reload fidelity.

### FE-01 — Applying or rolling back can hide the outcome immediately

**P1 · high confidence · callback reproduction and API trace.** `frontend/src/components/apply-mitigation-dialog.tsx:164` invokes `onApplied` for any non-dry HTTP 200, including blocked/failed/uncertain results. `frontend/src/pages/Dashboard.tsx:278` and `frontend/src/pages/Mitigations.tsx:219` close the dialog immediately. A mocked uncertain response invoked the close callback. The rollback handler also discards the structured result (`Mitigations.tsx:542`, `:760`).

**Correction/acceptance:** Keep results visible until explicit dismissal and refresh surrounding data independently. Show original/new action IDs, mixed outcomes and uncertainty. Test success, block, failure, uncertainty and transport ambiguity through each entrypoint.

### FE-02 — Incident screens can stay stale and report normal operation after a failed read

**P1 · high confidence · static request/render trace.** `frontend/src/pages/Mitigations.tsx:901` loads rule/settings/alert snapshots on mount without polling or a user refresh control. Failed rule reads become `[]`, which line 123 describes as normal operation. A newly firing rule can remain absent indefinitely while the separately polling sidebar changes.

**Correction/acceptance:** Refresh incident datasets on a bounded cadence plus focus/manual refresh, reject old responses, retain last-known data with age and represent loading/error/empty distinctly. Test clear→firing, new uncertain actions, failed reads and API recovery.

### FE-03 — Unknown or remotely changed settings look safely disabled

**P1 · high confidence · static request/render trace.** `frontend/src/pages/Settings.tsx:146` loads once and sets settings NULL on error. Lines 176–284 then label NULL as observe, automatic-off and unlocked. The page can also retain obsolete settings after another administrator arms the system. Disarm writes have no visible rejection handling (`:195`).

**Correction/acceptance:** Model unknown/cached/confirmed safety state explicitly, refresh coherently and display failed mutations. Test settings/status endpoints failing independently, remote mode changes and rejected disarm; unknown must never be labeled observe or disabled.

### FE-04 — Interface protection has no usable GUI workflow

**P1 for commissioning the documented safeguard · high confidence · whole-frontend search and serialization reproduction.** The handbook (`frontend/src/pages/Documentation.tsx:671`) asks operators to mark protected interfaces, but no frontend view reads the returned `protected` flag and no caller invokes `setProtected`. Its unused implementation (`frontend/src/lib/api.ts:787`) also double-serializes JSON through the helper at `:657`. `backend-rust/src/api/interfaces.rs:250` expects an object. The guard exists and can be configured through the authenticated API; no server bypass is claimed.

**Correction/acceptance:** Display persisted protection, add a `manage_devices`-gated control and send a plain JSON object. Verify save/reload, viewer restrictions and protected labels in disruptive-action pickers while retaining server refusal.

### FE-05 — Selecting SSH authentication “none” leaves SSH configured

**P2 · high confidence · actual callback with mocked API.** `frontend/src/pages/device-detail/device-settings-tab.tsx:233` omits all SSH fields when `none` is selected, then reports success. `backend-rust/src/api/devices.rs:483` preserves omitted values. Existing credentials remain active while the form shows none.

**Correction/acceptance:** Remove the unsupported transition for already-configured devices and display persisted authentication state; keep `none` for never-configured devices. An explicit credential-removal feature would require a separately defined audited API. Test configured-device edits cannot claim SSH was removed.

### FE-06 — Bundle creation leaves a hidden partial rule when the second write fails

**P2 · high confidence · source-callback reproduction and backend transaction trace.** `frontend/src/pages/Rules.tsx:181` posts BGP and MSS actions separately and updates displayed state only after both. The mock API accepted the first action, then rejected the second; the UI showed zero actions and did not refresh its parent. Retry repeats the first POST. Independently, `backend-rust/src/api/rules.rs:1498` confirms each add commits separately, making a persisted partial bundle possible. The callback reproduction did not itself write BGP actions to MariaDB.

**Correction/acceptance:** Validate all actions first and persist an ordered batch atomically, with retry identity and post-error reconciliation. A second-item validation/write failure must commit nothing; a lost response/retry must not duplicate the bundle.

### FE-07 — A late response restores an obsolete preview and token

**P2 · high confidence · delayed-response callback reproduction.** `frontend/src/pages/ManualReroute.tsx:113` accepts responses without a generation check while form edits clear the preview. Router A's delayed response repopulated its commands/token after selection changed to B. Inventory loading in `action-params-form.tsx:52` has the same old-device-response risk. Correct server binding normally refuses the mismatched token.

**Correction/acceptance:** Bind responses to request generation and immutable field snapshots; ignore superseded preview/inventory results. Test out-of-order completion after device/template/parameters/reason changes and clear recovery from expired/used tokens.

### FE-08 — Valid but old telemetry is presented as current

**P2 · high confidence · source/API comparison.** `frontend/src/pages/device-detail/interfaces-tab.tsx:60` displays values based only on `valid_sample`; it ignores `sampled_at`. The BGP card similarly ignores `last_polled_at`. The API intentionally preserves last-known rows, so old traffic/peer state remains visually live while collection is stopped or failing.

**Correction/acceptance:** Share freshness classification and visibly show age/cached/unknown states. Test old-but-valid samples, NULL timestamps, disabled collection and failed refresh without discarding useful historical values.

### FE-09 — Safety labels confuse dry runs, observe mode and SSH readiness

**P2 · high confidence · source/response-shape comparison.** `frontend/src/components/apply-mitigation-dialog.tsx:59` labels every would-run response observe, including an enforce dry run with an execution token. `device-detail/overview-tab.tsx:129` labels SSH readiness as automation active without checking mode, switches or locks. Flow and credential descriptions also retain removed behavior (see STD-07).

**Correction/acceptance:** Pass explicit preview/mode context and label SSH capability as readiness rather than permission to execute. Verify observe, enforce preview, disabled automation and locked devices each get accurate copy.

### FE-10 — Summed rules disappear from member-interface coverage views

**P2 · high confidence · contract/render trace.** `frontend/src/pages/DeviceDetail.tsx:118` and `InterfaceDetail.tsx:370` only count direct `interface_id`. Aggregate rules instead return `member_interface_ids`, so an interface covered by a summed rule can be described as having no rules.

**Correction/acceptance:** Include explicit group membership when counting/filtering and label summed targets. Test single, summed, mixed and cross-device rules without duplicate counts.

### FE-11 — Chart units and smoothing labels misrepresent measurements

**P2 · high confidence · source/data comparison.** `frontend/src/pages/InterfaceDetail.tsx:470` labels per-interval error/discard deltas as pps; 300 errors over 30 seconds displays 300 rather than 10 errors/s. Smoothing labels claim minutes (`:96`) while `lib/telemetry.tsx:156` averages N sample points and can fill a NULL optic point from older values.

**Correction/acceptance:** Label the existing deltas per poll interval and the existing smoothing choices as Raw/3 samples/5 samples; preserve current NULL gaps. Verify 10/30/60-second polls and irregular/missing measurements display truthful units. Time-based smoothing can be separate feature work.

### FE-14 — Inventory refresh reports success even when every source fails

**P2 · high confidence · promise/result trace.** `frontend/src/pages/DeviceDetail.tsx:103` ignores all three `Promise.allSettled` outcomes, starts unawaited reloads and always announces refreshed inventory. Operators can believe stale canonical inventory was renewed when every discovery failed.

**Correction/acceptance:** Inspect every result, await relevant reloads and report source-level success/partial/failure with age. All-failed and reload-failed cases must never show an unconditional success.

### FE-15 — Editing an egress rule silently retargets it to ingress

**P2 · high confidence · exact editor/API trace.** `frontend/src/pages/rules/rule-dialog.tsx:154` hardcodes ingress into both create and update payloads; line 351 displays a disabled ingress selector. The API supports egress and persisted rules can use it. Renaming such a rule in the GUI silently changes its traffic direction.

**Correction/acceptance:** Preserve the stored direction for edits and restrict the ingress default to creation. Test name/threshold/recovery edits of an egress rule leave its direction unchanged.

## Accepted choices and verification limits

- No hosted CI remains an explicit owner decision. The local release gate is the required verification path; restoring hosted CI is not part of this roadmap.
- SNMP v2c, legacy IOS SSH algorithms, first-contact TOFU and UDP source-IP identity remain documented management-plane risks. The existing substring verifier is also an accepted limitation; accepting incomplete reads as completed verification is a distinct implementation defect.
- Provider/asset actuators, Cloudflare/FlowSpec/scrubber execution, arbitrary CLI execution, per-action password/TOTP and template auto-expiry remain de-scoped. Historical migrations and audit documents remain historical evidence, not unused code to delete.
- ADR-0001 deliberately retains real-database tests and defers a database persistence seam. No speculative abstraction rewrite is proposed.
- No live device actuation, packet-capture interoperability, browser end-to-end run, screen-reader session, load/soak test, production-data inspection, Cloudflare configuration check, real upgrade/restart or MySQL 8.4 test was performed. Responsive/accessibility conclusions are source-based or lightweight mock checks as identified, not a complete WCAG certification.
- Frontend automated tests were previously deferred. The concrete regressions here justify focused tests in the corresponding fixes; absence of a test runner alone is not a new vulnerability.
- Uniform sFlow sampling per exporter and limited NetFlow sampler scope remain documented compatibility assumptions. IPv6 extension-header walking, IPFIX, extended-router ASN decoding and counter samples remain outside current implementation. Mixed-sampling fixtures reproduced the documented limitation; they are not counted as a new unacknowledged defect.

### Maintenance ledger and unverified leads

- Align remaining stale copy with the implemented model: nonexistent Tailwind/PostCSS files in the doctrine tree, missing Documentation route entries, de-scoped provider fixture examples, ADR references to hosted CI, daily-versus-ten-minute cleanup wording, five-versus-one-minute SSH stability text, and “create/rotate admin” wording where an existing password is not rotated. No new exploit or measured production regression is claimed for these leads.
