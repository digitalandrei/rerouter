# Rerouter — Security & Safety Audit (2026-06)

**Date:** 2026-06-26 · **Commit audited:** `12b254a` (main) · **Auditor:** Claude (Opus 4.8)

## 1. Scope & method

Full audit of the doctrine (`docs/doctrine.md`, `CLAUDE.md`) and the Rust
controller + React SPA, focused on security, safety-doctrine enforcement, clear
mitigations, and bugs.

Method: three parallel read-only Explore agents covered (a) the reroute execution
path and safety machinery, (b) auth / RBAC / API / web exposure, and (c) telemetry
parsers / detection / resource-safety. **Every P0/P1 claim was then re-read against
source by hand** before being recorded here — this matters, because the agents
produced several plausible-but-wrong "critical" findings (see §3). Severities below
are the verified ones.

This audit is read-only. No source files were changed. Fix sketches for the
"include and fix" hardening items are in §7 so a later session can apply them
directly. See also the prior `audit-remediation` work that closed 12/13 earlier
findings.

## 2. Headline: the core safety architecture is sound

No verified **P0** exists. The doctrine's central guarantees are enforced in code:

- **Observe-mode is GATE 0** in the single shared execution path
  ([executor.rs:115-128](../backend-rust/src/reroute/executor.rs#L115-L128)). The mode
  is read *fresh from `system_settings` in the DB* on every call
  ([settings.rs:29-44](../backend-rust/src/api/settings.rs#L29-L44)), and when it is not
  `enforce` the executor returns the rendered would-run plan and **executes nothing** —
  for both manual and automatic triggers, since both flow through `execute_with`.
- **Templates are the only execution path.** Execution begins by rendering a named
  template + validating params ([executor.rs:110-113](../backend-rust/src/reroute/executor.rs#L110));
  the device-CLI layer additionally refuses any command not on the allowlist.
- **The gate decision is a pure, ordered function**
  ([guard.rs:149-182](../backend-rust/src/reroute/guard.rs#L149-L182)): protected-iface →
  automatic master-switch → verify-or-refuse → maintenance-lock → device-lock →
  device-cooldown → rule-cooldown → rate-limit. Slot reservation happens under a
  per-device advisory lock ([executor.rs:151-155](../backend-rust/src/reroute/executor.rs#L151)).
- **Automatic requires both enables + enforce.** The automatic master-switch gates
  `trigger_type == "automatic"` ([guard.rs:153-156](../backend-rust/src/reroute/guard.rs#L153)),
  on top of the per-rule enable in the detection engine and enforce mode.
- **Crash recovery** marks any `pending/running/verifying` reroute `uncertain`, locks
  the device, raises a critical alert, and audits
  ([state_machine.rs:19-95](../backend-rust/src/reroute/state_machine.rs#L19-L95)). The
  state machine persists state **before and after** each side-effecting step.
- **"Sent" is never "succeeded."** State is `succeeded` only after verification; the
  message map is explicit ([executor.rs:207-214](../backend-rust/src/reroute/executor.rs#L207)).
- **Cookie posture is correct:** `HttpOnly + Secure + SameSite=Lax`, signed token,
  DB-backed sessions; no credentials are stored client-side
  ([sessions.rs:144-160](../backend-rust/src/auth/sessions.rs#L144-L160)).

## 3. False positives — do not re-flag

Recorded so the next audit (human or agent) doesn't waste a cycle on them. Each was
flagged "critical" by an agent and disproved by reading the code.

| # | Claim | Reality |
|---|-------|---------|
| FP-1 | SQL injection via `format!` in `replace_subscriptions` / dynamic UPDATEs | `table`/`fk_col` are **hardcoded string literals** at every call site (`"alert_subscriptions"/"recipient_id"`, `"webhook_subscriptions"/"endpoint_id"`; [notifications.rs:107,239](../backend-rust/src/api/notifications.rs#L107)); values are bound. The `devices.rs`/`rules.rs` UPDATE builders and the `collector.rs` prune loop likewise interpolate only literal column names. Not user-reachable. → tracked as P3 defense-in-depth. |
| FP-2 | IPv6 loopback bind bypass | The check **fails closed** ([config.rs:288-294](../backend-rust/src/config.rs#L288-L294)): a bare `::1`, `0.0.0.0`, or any public address fails `starts_with("127.")/"[::1]"` and the controller **refuses to start**. → tracked as P3 robustness (parse `SocketAddr`). |
| FP-3 | "Gigabyte" NetFlow allocation from `field_count` | `field_count` is `u16` → `Vec::with_capacity` ≤ 65535 × 4 B ≈ 256 KB, and the first out-of-bounds field read aborts the parse and frees it ([v9.rs:234-262](../backend-rust/src/telemetry/flow/v9.rs#L234)). Bounded per datagram. → tracked as P3 hardening (cap `field_count`). |
| FP-4 | Div-by-zero / NaN if `bucket_seconds = 0` | Guarded by `.max(1)` at the call sites ([collector.rs:644,677](../backend-rust/src/telemetry/flow/collector.rs#L644)). → tracked as P3 (enforce `≥1` in config validation for belt-and-suspenders). |

## 4. Verified findings

### P1 — fix soon

**P1-1 · Crash-recovery DB writes swallow every error.**
[state_machine.rs:36-84](../backend-rust/src/reroute/state_machine.rs#L36-L84) wraps the
uncertain-update, device lock, alert, and audit inserts in `let _ = …`, and
`recover_on_startup` returns `Ok(())` regardless. If the DB is unreachable or slow at
startup, recovery silently "completes": a crashed reroute stays `pending` and **the
device is never locked**, with no operator signal — a direct doctrine violation under
the exact failure mode recovery exists to handle.
*Fix:* check each write's `Result`, log failures at `error` with the reroute id, count
them, and on any failure emit a degraded-startup warning/alert (and consider returning
`Err` so the operator sees a hard signal) instead of `Ok(())`.

**P1-2 · Startup recovery is disableable by config.**
[state_machine.rs:20-26](../backend-rust/src/reroute/state_machine.rs#L20-L26): when
`safety.mark_running_actions_uncertain_on_startup = false`, recovery logs a warning and
`return Ok(())` — leaving in-flight reroutes in place. Doctrine states this behavior is
non-negotiable.
*Fix:* remove the runtime knob (always recover), or rename it to an explicit
unsafe-opt-in env var that logs loudly and is never settable from normal config.

**P1-3 · NetFlow exporter map is unbounded when the allowlist is off.**
[collector.rs:235-243](../backend-rust/src/telemetry/flow/collector.rs#L235-L243): with
`allowlist_enrolled_only = true` (recommended), unknown sources are counted and dropped
with **no allocation** — good. With the allowlist **off** (the off-by-default
collector's default), each unique source IP inserts an `Exporter` (templates + buckets),
so spoofed-source UDP floods grow the `exporters` HashMap until OOM. The collector
parses untrusted network input, so this is reachable without auth.
*Fix:* cap the exporter count (e.g. 10k, evict least-active) regardless of allowlist
state, and/or require the allowlist in production via config validation. Also bound the
per-bucket talker accumulation ([collector.rs:599-624](../backend-rust/src/telemetry/flow/collector.rs#L599)),
which grows with unique flows within a window before the top-K truncation runs.

**P1-4 · No re-authentication for the observe → enforce mode flip.**
[settings.rs:143-162](../backend-rust/src/api/settings.rs#L143-L162): a valid session
alone can flip the global safety mode (the change *is* audited). This is the single
switch that arms the entire system; a stolen/hijacked session can turn it on.
*Fix:* require a fresh password + TOTP (session `reauth_at` freshness) for the mode flip
and other admin-only settings changes. Note: *per-trigger* re-auth was deliberately
de-scoped earlier — this finding is specifically about the global arming switch, which
is a different risk tier.

### P2 — hardening / correctness

**P2-1 · Argon2 uses library defaults.**
[password.rs:14,24](../backend-rust/src/auth/password.rs#L14): `Argon2::default()` for both
hashing and verification. Correct algorithm (Argon2id v19) but the cost is whatever the
crate ships. *Fix:* pin explicit OWASP params (m=19456 KiB, t=2, p=1) so cost can't
silently regress on a dependency bump. Verification reads params from the stored PHC
string, so existing hashes keep working.

**P2-2 · CSRF defense rests solely on `SameSite=Lax`.**
[sessions.rs:151-160](../backend-rust/src/auth/sessions.rs#L151-L160). `Lax` blocks
cross-site POST but not all request shapes, and there is no anti-CSRF token on
state-changing endpoints (manual reroute trigger, settings, user/device mgmt). *Fix:*
add a double-submit CSRF token for POST/PUT/DELETE/PATCH, or move to `SameSite=Strict`
if the workflow tolerates it.

**P2-3 · Recovery codes share the password lockout counter.**
[auth/mod.rs:339-345](../backend-rust/src/auth/mod.rs#L339-L345): recovery-code
consumption is gated only by the shared `failed_login_attempts` lockout, so codes can be
ground against the same generous budget as passwords. *Fix:* give recovery codes a
separate, stricter counter (e.g. 3 attempts → 1h lockout).

**P2-4 · Untrusted-byte hardening in the NetFlow v9 parser.**
[v9.rs:240,286,245,291](../backend-rust/src/telemetry/flow/v9.rs#L240): cap `field_count`
and combined `scope_pairs + option_pairs` to a sane max (e.g. 256), and use
`checked_add` for `record_len`. Bounded today (FP-3) but cheap defense-in-depth against
a hostile/buggy exporter, and the parser is doctrine-bound to "never panic."

**P2-5 · `CF-Connecting-IP` is stored without validation.**
[api/mod.rs:256-263](../backend-rust/src/api/mod.rs#L256): the header is trimmed and
stored into `audit_logs.ip_address` with no format check, letting a spoofed/garbage
header pollute the audit trail. *Fix:* `parse::<IpAddr>()` and fall back to the socket
peer (or `unknown`) on failure.

### P3 — best-practice / noted

- **Retention/cleanup is a TODO** ([config.rs:121](../backend-rust/src/config.rs#L121)):
  audit/flow tables grow unbounded → eventual disk-exhaustion DoS. Implement the prune
  scheduler against the existing `retention.*` settings.
- **FP-1 follow-through:** centralize the subscription table/column identifiers (e.g. an
  enum) so the literal-only invariant is enforced, not merely observed.
- **FP-2 follow-through:** parse `SocketAddr` and use `.ip().is_loopback()` for the bind
  guard instead of string prefixes.
- **FP-4 follow-through:** enforce `flow.bucket_seconds ≥ 1` in `Config::validate`.
- **Per-query timeouts** in the detect loop and SNMP cross-calibration
  ([collector.rs:635-694](../backend-rust/src/telemetry/flow/collector.rs#L635)) so one
  slow device/DB query can't stall evaluation for the rest.
- **SNMP poll fails the whole device on a single walk timeout**
  ([snmp.rs:549-618](../backend-rust/src/telemetry/snmp.rs#L549)): per-walk retry would
  cut false "device down" alerts.
- **NetFlow template cache never evicts**
  ([v9.rs:78-99](../backend-rust/src/telemetry/flow/v9.rs#L78)): add LRU/TTL for
  high-churn exporters.
- **No audit row** when a low-confidence flow rule is auto-suppressed
  ([engine.rs:689-696](../backend-rust/src/detection/engine.rs#L689)); the suppression is
  only logged, leaving an audit gap.

## 5. Doctrine observations (design, not bugs)

- **Manual + no-verify-step is allowed by design.** The verify-or-refuse gate blocks
  only automatic triggers ([guard.rs:157-161](../backend-rust/src/reroute/guard.rs#L157));
  a manual run on a template with no verify step proceeds but the state machine forces
  `uncertain`. However, the API still returns `executed: true`. Recommend a one-line
  doctrine note ("`executed` ≠ `succeeded`; read `state`") so the UI/automation can't
  misread an uncertain action as a completed one.
- **Uncertain-acknowledge clears the lock on a free-text note alone**
  ([reroutes.rs:310-365](../backend-rust/src/api/reroutes.rs#L310)) — no forced state
  re-verification or rollback before the device is unlocked. Consider a guided
  "verify-before-ack" (show the verification command / offer a rollback template) so an
  admin can't clear a lock without confirming the real routing state.

## 6. Summary

| Severity | Count | Themes |
|----------|-------|--------|
| P0 | 0 | — |
| P1 | 4 | recovery error-swallowing, recovery disable knob, exporter-map DoS, mode-flip re-auth |
| P2 | 5 | Argon2 params, CSRF token, recovery-code lockout, NetFlow byte hardening, CF-IP validation |
| P3 | 7+ | retention cleanup, identifier/bind hardening, timeouts, SNMP retry, cache eviction, audit gap |
| False positives | 4 | literal-only SQL, fail-closed bind check, u16-bounded alloc, `.max(1)`-guarded div |

**Verdict:** the safety-critical core (observe-default, single-path gating, locks,
crash recovery, verify-before-success) is implemented correctly and defensively. The
real risks are operational hardening: making crash-recovery failures *loud*, bounding
untrusted-UDP memory, and adding re-auth to the global arming switch.

## 7. Appendix — fix sketches for the "include and fix" items

> Sketches only; not applied in this pass. Re-verify against current source before use.

**A. Argon2 explicit params** (`auth/password.rs`):
```rust
use argon2::{Algorithm, Argon2, Params, Version};
fn hasher() -> Argon2<'static> {
    let params = Params::new(19_456, 2, 1, None).expect("valid argon2 params");
    Argon2::new(Algorithm::Argon2id, Version::V0x13, params)
}
// use hasher() in both hash() and verify()
```

**B. Crash-recovery error visibility** (`reroute/state_machine.rs`): replace each
`let _ = sqlx::query(...).await;` with a matched result that `tracing::error!`s on
failure and increments a `failures` counter; after the loop, if `failures > 0` emit a
`recovery_degraded` alert and surface it in startup logs (optionally return `Err`).

**C. Bound the NetFlow parser** (`telemetry/flow/v9.rs`):
```rust
const MAX_FIELDS: usize = 256;
if field_count as usize > MAX_FIELDS { return Err(FlowError::TooManyFields(template_id)); }
// ...
record_len = record_len.checked_add(flen as usize).ok_or(FlowError::RecordTooLarge)?;
```

**D. Cap exporters** (`telemetry/flow/collector.rs`): before `entry(src_ip).or_insert_with`,
if `st.exporters.len() >= MAX_EXPORTERS && !st.exporters.contains_key(&src_ip)`, drop the
datagram (count it) or evict the least-recently-seen exporter.

**E. Enforce `bucket_seconds ≥ 1`** (`config.rs::validate`): `anyhow::bail!` if
`self.flow.bucket_seconds == 0`.
